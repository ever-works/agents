# Task: Respond to a specific objection

Draft a response to the prospect objection below. Prefer a verbatim
entry from the objection library when one fits; otherwise draft fresh
and propose it as a new library entry.

## Inputs

- Prospect name: {{prospect_name}}
- Company: {{company}}
- Channel: {{channel}}
- Original objection (verbatim from prospect): {{objection_text}}
- Stage of conversation: {{stage}} (touch 1 reply | mid-thread | post-demo)
- ICP score: {{icp_score}}
- Objection library reference: {{objection_lib_ref}}
- Approved proof points (KB): {{proof_kb_ref}}

## Steps

1. Classify the objection into one of: price, timing, authority,
   need, trust, competitor, fit. If it doesn't fit any, classify as
   "novel" and flag for owner review.
2. Search the objection library for the closest match. If a verbatim
   response exists for this exact class and stage, use it.
3. If no verbatim match, draft a fresh response using the four-part
   structure: objection -> reframe -> proof -> ask.
4. The proof must cite an approved KB item (case study, doc link,
   metric). Do not invent a customer or a number.
5. End with one ask: book a 20-minute call, share a document, loop in
   a peer. Never more than one ask.
6. If the objection class is "novel", propose a new library entry —
   tag, classification, response — for the owner to approve.

## Output format

Render an Objection response set:

- Class: <one of the seven>
- Reframe: one sentence
- Proof: one sentence with KB citation
- Ask: one sentence
- Full reply text: ready to send, addressed to the prospect

If novel, append:

- Proposed library entry: tag, class, body

## Hard rules

Never use false-urgency. Never invent proof. Never promise a discount
or contract term. Escalate pricing-detail and legal/security
objections to the owner.
