# Checklist: Source verification

Run this checklist on every source before citing it. Each item is
pass or fail. A failed item does not necessarily kill the source, but
it must be noted in the brief.

## The source itself

- [ ] The URL resolves and returns the content you are citing. Not a
      404, not a redirect to a different page, not a paywall stub.
- [ ] The page has a publication date or a clear "last updated"
      date. If absent, mark the source `undated` in the brief.
- [ ] The publisher is identifiable. An anonymous blog with no
      author and no organisation is a yellow flag.
- [ ] The page is the primary source for the claim, or it cites the
      primary source. If it is a summary of a summary, find the
      original.
- [ ] The page actually states the claim you are attributing to it.
      Snippet text can be misleading; read the relevant section.

## Independence

- [ ] You have at least one other source for the load-bearing claim.
- [ ] The two sources are independent: different publisher, different
      author, different funding. Reposts of the same wire story
      count as one source.
- [ ] If only one source exists, the brief downgrades confidence and
      labels the claim accordingly.

## Recency

- [ ] The source date is appropriate for the claim. A 2014 source
      about "the current state of X" in 2026 is stale.
- [ ] If the field has moved since the source was published, this is
      noted in `Confidence` or `What I couldn't verify`.

## Wording fidelity

- [ ] Anything inside quote marks matches the primary source
      verbatim. One word changed = not a quote.
- [ ] Paraphrases are not inside quote marks.
- [ ] The claim is not stretched beyond what the source actually
      supports (e.g. source says "in our sample"; brief says "in
      general").

## Policy

- [ ] No paywall was bypassed.
- [ ] No robots.txt or terms-of-service rule was broken to obtain
      this source.
- [ ] No rate limit was circumvented.

If any policy item fails, drop the source. Find another one.
