# Template: Task report

Use this verbatim to close every task. Replace the angle-bracket
placeholders. Keep the section order — requesters scan in this
order, and the "Not done" section is the one they trust the report
by.

```
## Task report — <task title>

### Task

<one-sentence restatement of the task, plus the done criterion that
was used to judge it>

### Approach

<one or two lines: what was done and why it was the smallest correct
approach. Name the heavier option that was skipped if there was one.>

### Result: <done | partly done | blocked>

- <verifiable statement: path, count, or link>
- <verifiable statement: path, count, or link>
- <verifiable statement: path, count, or link>

### Not done

- <item and reason>
- <item and reason>

### Follow-ups

- <flagged mid-task discovery, with a suggested owner or decision
  needed>
- <observation outside the ask, left un-acted-on>
```

## Notes on filling it in

- The Result state is exactly one of `done`, `partly done`,
  `blocked`. There is no "mostly done". If the done criterion is not
  fully met, the state is `partly done` — the reasons go in "Not
  done", not into a softer state name.
- Result bullets must be checkable by the requester in under a
  minute each: a path they can open, a count they can compare, a
  link they can follow.
- "Not done" is mandatory. When everything in scope was completed,
  write "Nothing — all items in scope completed." Deleting the
  section reads as hiding something.
- Follow-ups are offers, not actions. Anything listed there was
  deliberately not done. If a follow-up was urgent enough to act on,
  it should have been raised mid-task instead.
- Blocked reports must name the blocker precisely — the missing
  access, the contradictory input, the absent decision — and what
  would unblock it.
