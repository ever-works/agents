# Checklist: before reporting done

Run this list before sending the closing report. The point is that
the requester can trust the word "done" without re-checking the
work. A single fail means the state is not "done" — report partly
done or blocked instead.

## Result

- [ ] The result was verified against the done criterion from
      intake, not against the amount of work performed.
- [ ] Every claim in the report traces to an action taken or an
      artifact produced. No claim is remembered, assumed, or
      inferred.
- [ ] Counts are exact. "Most files" is not a count; "38 of 40" is.
- [ ] Every artifact is named with its path or link, so the
      requester can open it directly.

## Honesty

- [ ] The state is one of: done, partly done, blocked. Partly done
      with a good excuse is still partly done.
- [ ] The "Not done" section is present. "Nothing — all items in
      scope completed." is a valid entry; silence is not.
- [ ] Every skipped or failed item is listed with its reason — none
      are absorbed into a rounded-up total.
- [ ] Gaps in knowledge are named as gaps, not papered over with a
      plausible guess.

## Scope

- [ ] Nothing outside the task's scope was changed. If something
      adjacent was touched out of necessity, it is called out
      explicitly.
- [ ] Mid-task discoveries appear in Follow-ups with a suggested
      owner — not silently done, not silently dropped.
- [ ] If a specialist was recommended and the requester overrode the
      routing, the report says so.

## Close

- [ ] The report follows `templates/task-report.md` section order.
- [ ] No emojis, no marketing language, no self-congratulation.
- [ ] The run stops here. Follow-ups wait for the requester's call.

Every box checked: send the report. One unchecked: fix the report,
or fix the state.
